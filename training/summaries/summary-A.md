# Сводка по страницам группы A (LK-контекст, 18 страниц)

Формат строки: `код | название | родительский раздел | краткое содержание`.

00.01 | Регистрация / Авторизация | Корень (оглавление) | Флоу регистрации и входа на Платформу МТС Exolve: email+пароль или МТС ID; требования к паролю (минимум 8 символов, только латиница, цифра, заглавная и строчная), подтверждение email ссылкой на 24 ч, восстановление пароля ссылкой на 3 ч. После регистрации создаётся ЛС в Onyma с тестовым балансом 300 ₽, кастомер в CMA и отправляется нотификация через Mindbox.

00.01.01 | 2FA | Регистрация / Авторизация | Двухфакторная аутентификация: дополнительный шаг с кодом из SMS при подписании договора, авторизации, восстановлении пароля и смене номера, а также блокировка входа после нескольких неудачных вводов постоянного пароля. Содержит протоколы встреч по заявлениям на восстановление доступа (кейсы ЮЛ/ИП/ФЛ, наличие ЭП, порог оборота более 100 тыс. руб/мес, роль ОИБ).

00.01.01.01 | Инструкция на изменение номера телефона | 2FA | Пошаговая инструкция по смене подтверждённого номера из 5 этапов: заявка в CRM на отношения по ЭДО, получение и проверка заявления, заявка на изменение номера, верификация в ЛКМ с подтверждением по email/звонком, изменение номера и задача в Jira. Заявка подаётся через ЭДО, лично в московском офисе (вторники 9:00–18:00) или сканом на почту (только портфель ОРКК); для тестовых клиентов смена недоступна; у статусов ожидания ответа таймаут 8 рабочих часов.

00.01.02 | CAPTCHA | Регистрация / Авторизация | Капча на регистрации и авторизации (с учётом будущей доработки по 2FA); каталоги для капчи созданы в облаке cloud-exolve, доступ в Yandex Cloud запрашивается через ИТ-отдел. Указаны ID каталогов b1gai7vsonos9ebrs68t и b1gmjm49s8m2mro3sddf.

00.01.03 | Запрет регистрации с подозрительных email | Регистрация / Авторизация | Чёрный список почтовых доменов, с которых нельзя зарегистрироваться в Личном кабинете разработчика (34 адреса, включая sksen.ru, deepcool.biz, gigabitz.xyz). Список пополняемый.

00.01.04 | Регистрация / вход через МТС ID | Регистрация / Авторизация | Альтернативный способ создания аккаунта и входа через МТС ID: подходит номер любого оператора, а набор шагов входа (одноразовый пароль из SMS и/или постоянный пароль) зависит от настроек в МТС Профиле. Регистрация и вход бесплатны, аккаунт МТС Профиля создаётся автоматически.

00.02 | Callback звонки | Корень (оглавление) | Callback — ресурс приложения для обратного вызова: проигрывание сообщения и/или синтез речи, типы дозвона (одновременно, по порядку, рандомно), онлайн-уведомления и запись разговоров; в карточке генерируется неизменяемый curl-шаблон с ID. Создавать и удалять callback могут потенциальный и активный пользователи без ограничений, заблокированный и замороженный — только просматривать созданные.

00.03 | SDK | Корень (оглавление) | SDK как готовые библиотеки для встраивания телефонии в приложения: Mobile SDK — звонки в мобильном приложении, Web SDK — в окне браузера. Оба построены на стандарте WebRTC, звонки идут через SIP-протокол.

00.03.01 | Mobile SDK | SDK | Mobile Voice SDK для iOS/Android/Huawei (отдельно есть Flutter и ReactNative): звонки приходят в push-уведомлениях, нужен собственный бэкенд клиента со связкой device_id, подключение требует ключей APNS/Firebase/AppGallery. Есть блок «Неофициально» (удержание, холодный перевод, DTMF, конференция до 5 линий) и чек-лист запуска услуги по 6 разделам.

00.03.02 | Web SDK | SDK | Web Voice SDK для совершения и приёма звонков в окне браузера через SIP/WebRTC: услуга подключается бесплатно, оплачиваются только исходящие вызовы по тарифам. Сценарий старта из 6 шагов, есть демо-ссылка, чек-лист вынесен в Mobile SDK.

00.04 | SIP-соединения | Корень (оглавление) | Разъяснение двух разных понятий: SIP ID — идентификатор пользователя в VoIP-сети формата «имя@домен», Static IP — постоянный IP-адрес оборудования; оба используются для SIP-соединений. Приведены адреса: 80.75.130.99 (Static IP), 80.75.130.100 (SIP ID), 80.75.130.101 (переадресация на SIP).

00.04.01 | SIP ID (SIP-аккаунты) | SIP-соединения | SIP ID как ресурс приложения: аккаунт с автоматически сгенерированными юзернеймом и паролем, ограничения 5 cps и 300 sl для ЮЛ/ИП и 0,3 cps и 3 sl для ФЛ, поддерживается мультирегистрация. 3 SIP ID бесплатны, каждый следующий — 90 ₽/мес; удаление безвозвратно, доступно потенциальному и активному пользователям.

00.04.02 | SIP-транки (Static IP) | SIP-соединения | SIP-транк — виртуальный канал для выхода в PSTN: создаётся активными пользователями по API и в ЛК, обязательны внутреннее название, уникальный для системы IP-адрес и определяемый номер, порт по умолчанию 5060. Создание бесплатное, тарифицируются исходящие вызовы; есть раздел Roadmap (управление в ЛК, несколько портов на IP, пропускная способность, доп. CPS).

00.05 | Голосовые SMS (автообзвон) | Корень (оглавление) | Автообзвон двумя способами: аудиофайл из библиотеки приложения (студийная запись или синтез) либо онлайн-синтез текста при звонке. Ресурс голосового SMS создаётся бесплатно (название, аудиофайл, опциональный перевод на оператора), запуск через MakeVoiceMessage, тарификация как исходящий звонок плюс плата за синтез; в тестовом периоде звонки только на свой подтверждённый номер.

00.06 | Документы | Корень (оглавление) | Два типа документов: юридические (договор, доп.соглашения в разделе «Мои документы») и бухгалтерские (закрывающие — в «Мои финансы» → «Отчётные документы»); скачивание в PDF. В отличие от других продуктов МТТ, доп.соглашения при подключении услуг, бланки заказов и документы при отказе от номера не формируются — достаточно записи в Журнале действий.

00.06.01 | Изменение данных договора | Документы | Ручной процесс: заявка клиента → заявка на верификацию регистрационных данных в CRM → решение верификации (согласовано, не согласовано с блокировкой из-за фрода, согласовано с комментариями) → изменение данных в Onyma, CRM и ЛКМ. Заявки в ДПР в Jira нужны только для смены даты договора; ИНН и ОГРН для ЮЛ и ИНН для ИП меняются только через ДПР. Автоматизированный процесс намечен на 26Q1 и находится в разработке.

00.06.02 | Подписание договора | Документы | Подписание договора для снятия ограничений тестового периода: ЮЛ — через ЭДО, ИП — ЭДО или Госуслуги, ФЛ — Госуслуги; данные проходят автоматическую (фрод, терроризм, утерянный паспорт, ликвидация организации) и ручную верификацию. Отдельно зафиксированы семь дат договора в разных системах и соответствие адресов между ЛКР, договором, CMA и CRM.

00.06.02.01 | Авто ЭДО | Подписание договора | Упрощённая схема подписания договора юрлицом через ЭДО из 7 шагов: анкета в ЛКР (оператор ЭДО и ID участника, данные компании, реквизиты, адреса, контактное лицо), авто-верификация, ручная верификация в CRM, автопоиск контрагента и отправка договора в ЭДО, подписание УКЭП, верификация подписанного договора, активация аккаунта в Onyma. При отказе аккаунт не блокируется, а остаётся в тестовом режиме; дата в шапке договора = дата договора в CRM = дата заключения в биллинге.
