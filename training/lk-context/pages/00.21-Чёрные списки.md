# Чёрные списки

Введение
========

Чёрный список (ЧС) – бесплатная услуга автоматического отклонения вызовов с нежелательных номеров с/без предварительным аудиоинформированием звонящего. Представляет собой список номеров с опциональным кратким описанием причины добавления в ЧС для каждого из них. ЧС применяется ко входящим вызовам на все номера приложению. На Q2'24 применимо только к УВВ.

Документация по API-методам в Сообществе: [Blacklist API](https://docs.exolve.ru/docs/ru/api-reference/blacklist-api/)↗

Описание
========

В разделе "Чёрный список" ЛК отображается список номеров, добавленных в ЧС. Возможно выбрать из аудиобиблиотеки приложения аудиофайл, который нужно проиграть звонящему перед автоматическим завершением вызова. Такие отклонённый звонки пока (на Q2'24) не отражаются в Истории звонков.

Возможности:

* добавить в ЧС с описанием причины – номер вводится полностью. добавление по маске/региону пока недоступно
* удалить из ЧС (единично/массово)
* установить / удалить аудио для информирования звонящего перед отбоем

Протоколы встреч
================

Повестка:

**Цель**:

Договориться об оптимальном развитии услуги черных списков на единой платформе

**Как хочется сделать:**

Для VB важно создавать отдельный ЧС для каждого робота. Приложение получает и свой ЧС, и все ЧС его роботов. При этом общий ЧС приложения НЕ влияет на ЧС отдельного робота.

1. Черный список в исходящих звонках робота работает только на исходящие звонки робота
2. Черный список во входящих звонках робота работает только на входящие звонки робота
3. Черный список из ЛКР не влияет на роботов: стоит учесть, что сейчас мы входящие не будем принимать с номеров, которые в ЧС приложения (это опциональный пункт, в первой версии можно не делать)
4. Черные списки роботов не отображаются в ЛКР

**Проблема:**

В ЛКР ЧС создаётся на приложение в целом, этот ЧС влияет на всех роботов, подключенных к этому приложению. «Игнорирование» ЧС - это большая доработка платформы.

**О чём договорились** в результате встречи:

* ЧС приложения остаётся таким, каким был
* ЧС робота живёт только в роботе
* ЧС отдельного робота не влияет на вход. вызовы на все номера приложения
* Перед тем, как инициализировать исх. вызов, звонилка (сервис Роботов) проверяет по своему ЧС контакт и только после этого - по ЧС приложения
* Решение не затронет платформу, но пойдёт в техдолг
* В рамках одного робота может быть 1 ЧС на вход (в будущем) и 1 ЧС - на исход
* Концепция  1 приложение-много роботов сохраняется
